# Сайт Королёва — сборка для GitHub Pages

Это готовый статический сайт. Python, Flask, pip, npm и сборка на GitHub не нужны. Основа — последняя совместная версия сайта. Применены заключительные правки заказчика к подвалу, цветам разделов и кнопок, регистру названия услуги и размеру кнопки опыта. Меню в шапке сохранено. Переходы внутри квалификации проверены.

## Как разместить

1. Распакуйте архив на компьютере. Внутри находятся `index.html`, `attestats.html`, `privacy.html`, папки `static`, `expert`, `services`, `practice` и файл `.nojekyll`.
2. Откройте репозиторий на GitHub → **Add file → Upload files**. Загрузите содержимое распакованной папки, сохранив папки и подпапки. Сам ZIP-файл загружать вместо сайта не нужно.
3. Важно: `index.html` должен лежать непосредственно в корне репозитория — рядом с папкой `static`, а не внутри дополнительной папки `korolev-github-pages`.
4. Сохраните файлы: **Commit changes**.
5. Откройте **Settings → Pages**.
6. В **Build and deployment → Source** выберите **Deploy from a branch**.
7. Выберите ветку с загруженными файлами (обычно **main**) и папку **/(root)**. Нажмите **Save**.
8. Дождитесь завершения публикации. Адрес появится там же в Settings → Pages. Для обычного репозитория адрес имеет вид `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/` — подставьте собственные данные.

Если в репозитории лежит прежний Flask-проект, замените его публикуемую структуру файлами этой сборки; убедитесь, что не осталась старая настройка публикации из `/docs` или неподходящий workflow. Для предложенного способа источник должен быть **Deploy from a branch → нужная ветка → /(root)**.

## Что важно

- `.nojekyll` — служебный пустой файл. Он должен быть загружен вместе с сайтом; на некоторых компьютерах файлы с точкой в начале скрыты.
- Все ссылки на страницы и ресурсы относительные. Сайт работает и в корне домена, и по адресу с именем репозитория в пути.
- Внутренние страницы — настоящие HTML-файлы. Их можно открывать напрямую и обновлять в браузере.
- Старые ссылки превью вида `#!/services/...` автоматически ведут на соответствующие новые страницы.
- Не добавляйте CNAME, если ещё не настроили собственный домен. Для запуска на стандартном адресе GitHub Pages он не нужен.
- Формы обратной связи нет, как и в согласованной версии. Телефон, почта, меню, галерея и увеличение документов работают без сервера.
- Серверная админка Flask на GitHub Pages не запускается. Она сохранена в ранее переданном Flask-проекте. Для текущей статической сборки изменения вносятся в HTML/ресурсы репозитория либо сайт заново экспортируется из исходного проекта.
- Не загружайте на публичный Pages файлы `.env`, пароли, базы, папку storage или исходные материалы заказчика. В этой сборке их нет; включены только публичные ресурсы сайта.
- Перед открытой публикацией владелец подтверждает допустимость размещения реквизитов на опубликованных сканах.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
